<Stage tag="MOTIVE" title="왜 만들었나">

학교 수행평가 과제로 시작한 프로젝트다. 그런데 만들고 나니 비슷한 포맷으로
쌓인 파일들 — 이를테면 `20230422.jpg` 같은 날짜별 사진 파일 — 의 이름을
새 포맷으로 반복해서 손으로 바꾸는 게 매번 귀찮았던 참이라, 과제 이후에도
계속 실제로 쓰게 됐다.

</Stage>

<Stage tag="BUILD" title="어떻게 만들었나">

작업 흐름은 네 단계다.

1. 작업할 폴더 경로를 입력받는다
2. 정규식으로 파일을 검색한다 — `(?P<year>\d{4})(?P<month>\d{2})(?P<day>\d{2}).jpg`
   처럼 그룹핑을 쓰면 파일명에서 변수를 추출할 수 있다
3. 필요하면 파일을 옮길 새 경로를 지정한다
4. 추출한 변수를 `{year}-{month}-{day}` 형태로 조합해 새 이름 패턴을
   만든다. `<파이썬 코드>`를 넣으면 그 자리에서 실행 결과를 바로 끼워
   넣을 수도 있고, 파일 순서를 나타내는 `Counter` 변수도 자동으로
   제공된다.

되돌리기 기능이 없다는 게 처음 버전의 가장 위험한 지점이었어서 실행 전
미리보기 단계를 필수로 거치게 만들어 실수를 줄였다. 이후 버전에서는
기초적인 복구 기능도 추가했다.

</Stage>

<Stage tag="RESULT" title="결과">

스타 3개를 받았고 "과제로 시작했는데 실제로 계속 쓰게 된 도구"라는 게
이 프로젝트의 진짜 결과였다. 정규식이라는 다소 딱딱한 도구를 파일 정리라는
아주 실용적인 문제에 적용해본 경험이었다.
