# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Astro static site on GitHub Pages. Astro was selected during repository setup for the requested blog and selectively interactive playground.

## Users

People reading the owner's introduction, projects, or articles, including potential peers and collaborators. The owner also needs a low-friction way to update the site.

## Product Purpose

A Korean personal website that brings the owner's portfolio, Velog-backed blog, and playground together. It should make both materials science and coding work understandable and easy to explore.

## Positioning

Present materials science and software as parts of one personal practice. Do not frame the owner as only a developer or reproduce a generic developer résumé.

## Operating Context

The site is published through GitHub Pages. Velog remains the source of blog posts, imported from RSS by GitHub Actions. Visitors should be able to reach the original Velog article and linked GitHub repositories. The owner should be able to maintain profile, project, and category data without editing layouts.

## Capabilities and Constraints

- Include an introduction/about area, selected projects with short GitHub-linked descriptions, a categorized blog, and a playground for interactive project pages.
- Refresh RSS data on a schedule and on demand. Preserve original URLs and dates, and keep the last good data if a refresh fails.
- The public site and its content are in Korean.
- Velog username, final public profile copy, and featured projects are undecided. Provide clear editable configuration and useful empty states; do not invent facts or posts.

## Evidence on Hand

The owner supplied the product requirements above, but no approved biography, Velog account, project list, article content, or visual assets. The repository currently has setup files and no implemented site pages.

## Product Principles

1. Give scientific and software work equal prominence.
2. Preserve Velog as the blog source and link back to original work.
3. Make routine content edits simple for the owner.
4. Keep the site usable before undecided personal details are filled in.
